# StockSim — Claude Code 프로젝트 지침

> **기능·데이터·API의 기준 문서는 `docs/SPEC.md`다.** 작업 전 해당 장을 읽고, 요구사항 ID(FR-xxx)를 커밋 메시지와 테스트 이름에 쓴다. SPEC으로 결정할 수 없는 건 구현하지 말고 질문한다.

## 프로젝트
코스피 시총 상위 30종목에 대해 (1) 5거래일 예측(상승확률·분위수 범위·근거·시나리오), (2) 모의투자, (3) 모델 성적표를 제공하는 웹 서비스. 교육·모의투자 목적이며 투자 권유가 아니다.

## 스택
- Backend: FastAPI, SQLAlchemy 2.x, Alembic, PostgreSQL(TimescaleDB), Redis, APScheduler
- ML: LightGBM(분위수 회귀 + 상승확률 분류), SHAP. 학습은 사용자의 Colab Pro에서 하고 이 레포에는 코드/추론만 둔다.
- LLM: Anthropic API는 시나리오 "설명문 생성"에만 사용 (예측은 ML 모델이 한다)
- Frontend: Next.js 14(App Router) + TypeScript + TradingView Lightweight Charts
- 폴더 구조는 이미 잡혀 있다. 새 파일은 기존 구조의 해당 위치에 둔다. 구조를 바꿔야 하면 먼저 이유를 설명하고 확인받는다.

## 데이터 소스 원칙 (중요)
- 크롤링을 기본 수단으로 쓰지 않는다. 공식 API를 쓴다.
- 과거 일봉·수급: pykrx (장 마감 후 배치용, 실시간 아님)
- 실시간 시세/호가: 한국투자증권(KIS) Open API 웹소켓. 개발 단계에서는 `MarketDataProvider` 추상화 뒤에 두고 구현체를 교체 가능하게 한다.
  - `PykrxEodProvider`: 종가 기반 (키 없이 개발/테스트)
  - `ReplayProvider`: 저장된 틱/일봉을 재생 (테스트, 백테스트)
  - `KisProvider`: REST 폴링 + 웹소켓 구독
- 공시: DART, 뉴스: 네이버 검색 API, 거시: 한국은행 ECOS
- KIS의 엔드포인트, tr_id, 웹소켓 접속 방식은 기억에 의존하지 말고 공식 문서를 확인한 뒤 구현한다. 문서와 다르게 동작하면 사용자에게 알린다.
- API 키는 `.env`로만 관리한다. 코드/로그/커밋에 키를 넣지 않는다.

## 코딩 규칙
- 금액은 정수(원)나 `Decimal`. float 금지.
- 잔고를 직접 수정하지 않는다. 모든 입출금은 `cash_ledger` 기록을 통해서만 변경한다.
- 체결 처리는 `주문 상태 + trades + ledger + positions`를 하나의 DB 트랜잭션으로 묶고, 계좌 행을 `SELECT ... FOR UPDATE`로 잠근다. 주문 ID 기준 멱등 처리.
- 세율/수수료율은 `fee_config` 테이블에서 읽는다. 하드코딩 금지. 시작 시점의 현재 세율은 사용자에게 확인을 요청한다.
- ML: 랜덤 분할 금지, walk-forward만 사용. 뉴스는 발행 시각 기준으로 장 마감 후 기사는 다음 거래일 피처로 매핑(미래 정보 누수 금지). 학습과 서빙의 피처 로직은 동일 코드를 공유한다.
- LLM 시나리오 프롬프트에는 "입력에 없는 사실은 쓰지 말 것"을 반드시 넣는다. 입력은 JSON(예측값, SHAP TOP5, 대표 뉴스, 시장 상황).
- 예측/성적표 화면과 API 응답 메타에 "교육·모의투자 목적이며 투자 권유가 아닙니다" 문구를 포함한다.
- AI 계정도 일반 사용자와 같은 주문 API/체결 엔진을 통과한다. 특별 경로 금지.
- 새 기능에는 테스트를 같이 쓴다. 특히 모의투자 엔진(상태 전이, 평단가, 비용, 동시성)은 필수.

## 작업 방식
- 한 번에 한 단계(Phase)만 진행한다. 끝나면 무엇을 만들었는지, 어떻게 실행/검증하는지, 남은 것을 요약한다.
- 실행해 본 것과 못 해 본 것을 구분해서 보고한다. 네트워크/키가 필요해서 못 돌린 건 그렇게 말한다.
- 불확실한 외부 API 스펙은 추측해서 채우지 말고 TODO와 질문으로 남긴다.

## 명령어
- `make up` DB/Redis, `make api` 서버, `make test` 테스트, `make collect` 데이터 수집, `make apitest` API 점검
